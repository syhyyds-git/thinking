Experiment Budget Brief

TIR-Bench 原论文训练预算与低成本方案

XSkill 与 Ace-Skill 的论文训练规模都是每种方法约 400 次训练 rollout。 将预算压到 100 次只能视为低成本 pilot；推荐至少保留 200 次，以便方法机制有机会产生可观测效果。

基准：TIR-Bench，5 类 训练集：100 测试集：200 协议：seed 42 更新：2026-06-06

先说结论

不建议直接把训练降到 100 次后，用结果判断 XSkill 或 Ace-Skill 是否有效。 100 次只相当于论文训练计算量的 25%，而且会削弱两种方法各自依赖的训练机制。 当前建议是：每种方法训练 200 次，先在相同的 50 个测试样本上各跑 1 次； 只有趋势明确后，再扩展到完整 200 个测试样本。

本页所说的 100 / 200 / 400 均指主 agent 的训练 rollout 数， 不等于训练阶段的全部 API 请求。轨迹摘要、经验批判、经验合并和技能生成仍会带来额外调用与 token 消耗。

为什么训练不能砍得太多

XSkill 会失去对比信号

论文设置让同一个任务产生多条独立轨迹，再从成功、失败和工具使用差异中提炼经验。 只有 1 条轨迹时，这一过程会退化为单轨迹总结。

Ace-Skill 的 sampler 尚未充分迭代

优先采样需要根据前面批次的结果不断更新分布。采样次数过少时， sampler 可能刚识别出难题，训练预算就已经耗尽。

弱模型更需要足够训练信号

当前 Qwen3.5-4B 在 TIR-Bench 上本身能力有限。若训练也大幅压缩， “没有提升”可能来自预算不足，而不一定来自方法无效。

三种方法必须使用同一批测试样本、同一模型、同一 max_turns、同一工具配置。 Vanilla Tools 不训练，只运行测试集，作为判断 skill/memory 是否真正带来提升的必要对照。

当前实验建议

第一步按每种方法 200 次训练 rollout 执行。 XSkill 使用 100 题 × 2 rollouts；Ace-Skill 保留 prioritized sampler， 执行 200 次采样，不改成顺序遍历。

测试先使用固定的分层 50 题，每种方法 rollout=1、max_turns=10。 若 XSkill 或 Ace-Skill 相对 Vanilla Tools 出现稳定提升，再扩展到完整 200 题测试。

结果解释边界

100 次训练：只能称为低成本 pilot。

200 次训练：可称为 50% 论文训练预算下的方法比较。

400 次训练：训练规模与论文一致，但模型、API 和 max_turns 等仍需单独对齐，才能称为严格复现。

可直接对外使用的说明

XSkill 与 Ace-Skill 在 TIR-Bench 上的原论文训练预算均约为 400 次 rollout。 受实验费用限制，我们计划先采用每种方法 200 次训练 rollout，即论文训练计算量的 50%： XSkill 对 100 个训练样本各执行 2 次 rollout，Ace-Skill 保留原有 prioritized sampler 并执行 200 次采样。 测试阶段先在同一组 50 个分层样本上，以 Vanilla Tools、XSkill 和 Ace-Skill 做公平对比。 该实验属于低预算复现与趋势验证，不等同于论文完整训练规模；若观察到明确提升，再扩展到完整测试集。

论文依据与口径

  1. XSkill, arXiv:2603.12056v2。TIR-Bench 使用 100 train / 200 test； Appendix B, Table 8 给出 Rollouts per Sample (N) = 4、Max Turns = 20。 本页据此计算训练主推理量为 100 × 4 = 400。
  2. Ace-Skill, arXiv:2605.08887v1。第 3.1 节 implementation details 给出训练 50 steps、batch size 8、每样本 1 rollout，因此为 50 × 8 × 1 = 400 次采样执行； TIR-Bench 最多 10 agentic turns。
  3. 两篇论文测试均采用多次 rollout 的 Avg@4 / Pass@4 口径。当前低成本方案将测试改为 rollout=1， 目的是先比较相对趋势，不应与论文表格中的 Avg@4 / Pass@4 数值直接横向比较。
  4. 本页的训练量以 agent rollout 为统一计量单位。XSkill 和 Ace-Skill 在 rollout 之外还会调用模型完成 trajectory summary、experience critique/merge 和 skill generation，因此真实 token 成本不能仅按 rollout 数线性计算。
