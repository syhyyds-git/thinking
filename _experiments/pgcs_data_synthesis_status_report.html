一、这个项目在做什么

我们正在为模型训练准备一套"基于证据的推理"训练数据。市面上现成的训练数据要么太简单（模型只会检索答案），要么太脱离专业场景（不懂临床、不懂金融）。我们的思路是：

拿公开权威的专业 benchmark 做骨架（HealthBench 临床、APEX 商业分析、Finance-Agent 金融披露），用真实公开数据源做证据（PubMed 文献、SEC 财报、NICE 指南等），用大模型把骨架实例化成具体题目。每道题都带着可验证的推理步骤和评分标准。

二、数据来源：3 个公开 benchmark

这三个 benchmark 都是公开、可查、有学术或工业背书的，我们用它们做骨架（不直接照搬原题，而是分析它们考察的能力维度）：

名称领域来源 / 出处考察什么
HealthBench 临床医学 OpenAI / Arcadia Institute 公开评测集 患者咨询、医生回复、用药调整、危险信号识别、共享决策
APEX 商业分析 / 咨询投行 公开商业建模评测集 DCF 估值、协同分析、商业尽调、法律风险评估
Finance-Agent v2 金融披露分析 公开 agent 评测集（v2 版本） 10-K/10-Q 解读、segment 分析、风险因子、契约合规
关键说明：我们不直接照搬这三个 benchmark 的原题，而是分析每道题考察的能力维度（比如"用药调整 + 多轮 + red-teaming"），归纳出 48 个任务族，再用大模型实例化成新的、风格一致但具体内容不同的题目。所以我们产出的数据风格对齐上游、内容完全自有、可商用。

三、48 个任务族：我们对原 benchmark 的归纳

"任务族"是什么？ 把同类任务的模式归纳出来就是一个族。比如 HealthBench 里有 100 多道不同的用药咨询题，它们考察的核心推理步骤是相似的（核对适应症 → 排查禁忌 → 评估药物相互作用 → 给出建议），归纳成"用药调整咨询"这一个任务族。

四、221 个具体场景：任务族的实例化

"场景"是什么？ 任务族是抽象的模式，场景是模式的一次具体实例化。同一个任务族，用不同的患者/客户/数据，可以变成多个不同的场景。

举例：「用药调整咨询」是一个任务族。在这个族下，"54 岁焦虑症患者问能否换药" 是一个场景，"高血压患者问能否停药" 是另一个场景。它们的推理骨架相同，但具体内容不同。

一个完整场景长什么样（HealthBench 示例）

用户问题（第一人称口语）
"我今年 54 岁，最近 6 个月一直在吃 escitalopram 20mg 治焦虑，最近失眠严重，上周自己减半了。我想长期换成 hydroxyzine，可以吗？"
参考答案（开头）
"直接长期换用 hydroxyzine 不是最优方案。SSRI 类（如 escitalopram）突然减半可能引起停药反应，hydroxyzine 长期使用也有其限制。我建议先和你目前的主治医生沟通，分两步处理：第一，恢复 escitalopram 原剂量或更换为半衰期更长的同类药；第二，针对失眠本身做单独评估..."
评分标准（共 3 项）
  • ① 提到 SSRI 突然减量会引发停药反应（权重 +2）
  • ② 建议恢复原剂量或换半衰期更长药物（权重 +2）
  • ③ 反对"直接长期换 hydroxyzine"作为单一方案（权重 -3，陷阱项）
每个场景都包含：1 道题 + 1 个参考答案 + 2-3 个评分项 + （可选）多轮对话历史。

逐步详解

第 1 步：取骨架

从我们已经做好的 48 任务族库里取一个。每个任务族带着核心推理步骤（如"用药调整咨询"族的 5 步：核对适应症 → 排查禁忌 → 评估相互作用 → 给出建议 → 提示监测）和考察维度（如多轮对话、red-teaming）。

第 2 步：挖材料

按场景类型去对应的公开数据源挖真实材料作为依据：

  • 临床场景 → 从 PubMed 拿文献摘要、从 NICE 拿英国临床指南、从 PMC 拿全文
  • 商业场景 → 从 SEC EDGAR 拿真实公司财报（XBRL 结构化数据）
  • 金融场景 → 从 SEC 10-K/10-Q、美国法院判例库拿材料

第 3 步：造实例

大模型（MiniMax-M3）读取骨架 + 挖到的真实材料，生成一个具体情景：具体的患者/客户、具体的数值、具体的对话背景。比如把"用药调整咨询"族 + 一段 escitalopram 文献，实例化成"54 岁焦虑症患者问换药"这个场景。

第 4 步：出题目

大模型读取实例，生成题目 + 参考答案 + 评分项。每个评分项有明确的检查规则（数值容差、关键词匹配、陷阱检测）。

第 5 步：组装

把题目、参考答案、（可选的）多轮对话历史、（可选的）附件材料组装成训练样本。最终产物：sft_samples.jsonl，可以直接用于模型微调。

合成材料（补充）

对于不需要外部依据的场景（如纯临床知识题、商业虚构案例），由大模型按骨架生成"合成材料"。40 个场景用了这种方式，主要在 HealthBench 临床知识题和部分 APEX 虚构商业案例上。

接入统计：221 个场景中，154 个（70%）用真实公开数据源，57 个（30%）用合成材料（合理设计，因为部分场景本来就不需要外部依据）。

七、待决策的 3 个问题

当前 221 道题已端到端跑通，进一步推进前需要先对齐 3 个方向性问题：

1 造多少数据合适？

当前 221 道。扩量目标量级（1k / 3k / 5k+）需要先对齐，决定后续是优先做"同任务族多实例化"还是"扩任务族"。

2 48 个任务族是否可行？

这 48 个族是从 HealthBench / APEX / Finance-Agent v2 三个原 benchmark 归纳得来的，需要决策两件事：

  • 来源合理性：这样的归纳过程能不能站得住脚，48 个族是否真的能从原 benchmark 推导出来，归纳方法是否系统、可复现
  • 数据泄漏风险：用从原 benchmark 归纳的骨架去生成新题目，新题目会不会跟原 benchmark 太像，导致模型在原 benchmark 评测时分数虚高
3 Finance-Agent v2 数据怎么造？

Finance-Agent v2 上游是 agent benchmark，原题带工具调用链（tool call trace）。我们的生成方案要不要模拟这层 agent 风格，需要决策。
