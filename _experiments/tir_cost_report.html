3. 为什么 Token 消耗增长如此之快

多轮对话的上下文累积

每一轮都会重新发送完整对话历史（包含之前所有的图片）。图片被编码为 Token，因此输入 Token 数随轮次线性增长。

第1轮：系统提示 + 问题 + 1张图片 ≈ 15K
→
第2轮：历史 + 工具返回图片 ≈ 30K
→
第3轮：历史 + 工具返回图片 ≈ 45K
→
第N轮 ≈ N × 15K
14 轮对话 → 单次 rollout 累积输入 ≈ 1.5M Token

训练阶段 = 每样本 4 次独立 Rollout

Rollout 1 (~1.5M)
+
Rollout 2 (~1.5M)
+
Rollout 3 (~1.5M)
+
Rollout 4 (~1.5M)
=
~6M / 样本

+ 经验生成阶段（训练后处理）

所有 Rollout 完成后，系统分析工具输出的图片（4 次 Rollout × ~15 张图片 = ~60 张），生成经验总结、批评和技能文档。此阶段额外增加约 ~450K Token / 样本。

7. 已知问题与建议

#问题严重程度建议
1模型过度使用 code_interpreter，不收敛到最终答案高 提示工程：添加"在 N 轮内给出最终答案"指令
2经验生成发送图片过多 → "多模态数据损坏"错误中 限制每批图片数 ≤10
3经验分解返回空（缺少系统消息）中 确保所有 MiMo API 调用包含系统消息
4SSL / 网络不稳定中 添加指数退避重试机制

8. 下一步计划

  1. 确定 rollouts_per_sample：4（论文原始设置）vs 2（节省成本）。这是最大的成本杠杆。
